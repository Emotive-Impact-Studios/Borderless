# Borderless native implementation

Read `../docs/VISION.md`, `../docs/CODEX_BRIEF.md` and `../design-system/docs/CODEX.md` first. The approved stack is Swift/Rust agents, LiveKit, a shared TypeScript front end and Tauri Wall; Go/.NET/Godot units below are retained as reference. These components are intended to remain in the shipping architecture. They are not a completed replacement application.

| Directory | Actual code now | Still missing |
| --- | --- | --- |
| `core` | Dependency-free Rust display-coordinate mapping and complete-frame health policy, C ABI, eight tests. | Display creation, encode/decode, native transport, input leases. |
| `macos` | Reusable Swift ScreenCaptureKit service, system picker, bounded latest-frame mailbox, local preview, stop and Rust health binding; local real capture/update/Stop accepted on 3 November after capture-service recovery. | Encoder/network path, personal receiver, full native host integration and virtual display. |
| `dotnet` | Rust P/Invoke, trusted-origin room pairing/snapshot/live client, fragmented bounded WebSocket receive, validated Wall model, executable conformance checks. | Full commands/reconnect/media and Windows OS host. |
| `wall` | Buildable Godot C# scene using the room client; actual note text/owner/geometry, stable nodes and removal; engine smoke test. | File/media/ink/quiz renderers, interactive shared layout, viewport/world migration, full spatial experience/accessibility. |
| `hub` | Compiled Go strict move-envelope validation and trusted actor/ownership/version policy, race-tested. | Complete Go server, persistence, receipts, assets, live routing and migration parity. No Go server is launched. |
| `windows` | Exact adapter/driver boundary and pinned upstream entry points. | Windows capture/driver implementation, WDK build/signing and hardware acceptance. |
| `protocol` | Explicit compatibility versus proposed v1 boundary; C ABI/lifetime semantics. | Complete generated protocol schema and cross-client conformance suite. |

## Build and verify

Requirements: Node 24 and existing npm requirements; Rust 1.88 toolchain with fmt/clippy; Go 1.24.4 or compatible; .NET SDK 10.0.403; Xcode/Swift 6 on Mac. Godot .NET 4.7.2 is pinned by the Wall project. These are verified development versions, not a blanket long-term security support commitment. Upgrade/qualify toolchains before release.

```sh
npm ci --ignore-scripts
npm run verify
npm run native:verify
```

`native:verify` builds/tests Rust, Go, .NET and the real disposable-room client; on Mac it also builds/tests Swift. It compiles the Godot project. To run the engine scene gate, set `BORDERLESS_GODOT` to the official 4.7.2 .NET engine executable. Set `DOTNET_ROOT` if .NET is installed privately; the script puts the selected SDK on PATH. Optional `BORDERLESS_CARGO` / `BORDERLESS_DOTNET` override tool locations.

On this checkout:

```sh
BORDERLESS_GODOT="$PWD/output/native/tools/Godot_mono.app/Contents/MacOS/Godot" \
DOTNET_ROOT="$HOME/.dotnet" npm run native:verify
npm run native:mac:package
```

The local package is `output/native/Borderless Native.app`, ad-hoc signed for this machine, not Developer ID signed/notarised. Open it and use **Choose source** to select a disposable window through Apple's picker, observe first-frame status and use **Stop sharing**. The reusable capture service powers this diagnostic host; it has no room transmission yet. Do not confuse the verification window with the finished Borderless UI.

For the Wall, run Godot with `--path native/wall`. Connect using a trusted hub origin, room ID and one-use Wall pairing token generated by that room's leader. The token is cleared from the field when submitted. Current native Wall is read-only and renders notes; file viewer absence is visible. Closing/reopening and re-pairing is currently required for recovery. Never use leader credentials as a substitute for pairing.

The conformance script creates a temporary loopback hub, passes its token through stdin, then shuts it down and deletes only its disposable data. It never opens the user's saved room. Runtime data, packages, caches and toolchains are ignored. Source distributions include native source, not compiled dependencies.

## Acceptance boundaries

Compilation, library tests, headless engine rendering, OS picker/stop, actual captured frames, LAN transmission, physical phone gestures and virtual monitor enumeration are separate results. The initial native capture test here returned zero complete frames after OS selection; the adapter correctly reports missing frames, and that failure remains open. Do not relabel it as working capture.
