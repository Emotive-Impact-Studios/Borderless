## Verification environment

Native correction evidence is in [NATIVE_QA_2026-11-03.md](NATIVE_QA_2026-11-03.md). Existing Electron/browser rows below remain evidence for the compatibility implementation; they do not transfer automatically to Swift/Godot/Go. `npm run native:verify` is a separate gate and reports whether Godot engine execution was included.

- Node.js 24.22.1 on Apple Silicon macOS 14.5; Electron 45.2.1; Playwright 1.64.1 with installed Google Chrome.
- `npm test`: 54 passing integration/recovery/process/permission/client/spatial tests. Four new cases cover owner-only offers, recipient authority, invitation generation/expiry, targeted socket/capture binding, receiver closure and authenticated viewer routes. Original 29-test managed Linux checkpoint remains historical.
- Network tests start the hub and clients inside the same test process environment. They use actual sockets, HTTP, WebSockets and filesystem storage.
- Current source and unsigned directory app pass 35 checks with `BORDERLESS_QA_ICE_MODE=loopback`, including actual personal receiver windows and consent/teardown/recovery. Source samples 127 colours; package adds seven initial-offline samples for 134, all at least 4.888:1. Initial state/video faults are explicit QA injections. This is same-machine evidence, not a fix for normal interface-address ICE or physical LAN acceptance. See [QA_MAC_2026-11-03.md](QA_MAC_2026-11-03.md).
- Physical phones, a second physical client, trusted LAN certificate/QR and hardware display commissioning remain open. Local unsigned directory and read-only mounted DMG apps pass; the image checksum verifies. Developer ID signing/notarisation and quarantined-download acceptance remain open. Hosted media uses a controlled unicast test mode whose actual outcome must be checked separately; it cannot qualify LAN/mDNS or OS prompts.
- Remote GitHub Actions conclusions are separate from local results. Check the PR before relying on hosted CI.
