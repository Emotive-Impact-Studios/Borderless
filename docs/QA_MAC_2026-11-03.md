## Defects fixed during acceptance

- A macOS capture source dialog suspended Electron's main event loop and stalled the in-process room server. The hub now runs in its own utility process; HTTP remained responsive while the real picker was open. Automated acceptance also reproduces a blocked native thread.
- Active sharing had an icon-only toggle still labelled Share your screen. It now exposes a visible Stop sharing button and the correct accessible state. A pending source selection disables duplicate requests.
- Expired socket sessions could receive a room broadcast until the heartbeat retired them. Broadcast/outbound checks now close expired access immediately.
- Session credentials and command receipts accumulated indefinitely. Inactive session data now retires at startup and on the 30-second maintenance cycle, without deleting current-session retry receipts or saved contributions.
- The macOS 26 CI run rendered the captured source but could not receive peer media. The wrapper denied Chromium's newer `local-network`/`loopback-network` requests. A trusted-main-frame consent path now permits the operator to allow the requested connection; refusal, cross-origin/subframe access and navigation races are tested. macOS network usage/Bonjour metadata are declared. Controlled hosted acceptance later passed; OS prompt/LAN commissioning remains separate. Reference: [Electron permission API](https://www.electronjs.org/docs/latest/api/session), [Apple local network privacy](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy).

## Recovery and accessibility continuation

- Socket opening previously reported Live before its current snapshot. Readiness now requires hello plus fresh socket state; reconnect also preflights the current HTTP authority. A 401 stops retrying. The banner offers Reconnect now, then Join again/Leader login after access ends.
- A response lost after a committed command previously left the client unable to retry safely. One retry now reuses the original command ID and refuses a changed identity. A rendered Portal request was committed and deliberately aborted, then retried into exactly one note. Two lost replies stop after two requests and ask the user to inspect the canvas. Uploads are never automatically resent.
- An open thought draft and participant identity survive offline/reconnect while the leader revokes drawing; the fresh view is locked. Console approval, Portal contribution and theme-button focus survive live panel replacement. Nested file/return dialog Escape restores the original card. Removing a focused card returns focus to the canvas.
- The first hosted run of the continuation exposed a timing race: a queued dialog-close event could restore its stale opener after the user had already focused a Portal contribution. Explicit close now restores synchronously, and a delayed native close event preserves a newly chosen control. A dedicated real-browser regression covers that ordering; the file-return check also waits for the application's own acknowledgement/close.
- Focusable cards open with Enter/Space, move with arrows and resize with Alt + arrows; Shift increases the step. The same version/ownership commands enforce writes. A participant cannot keyboard-move another owner's card. Portal tabs pass Left/Right, Home/End, roving tabindex and panel labelling.
- Live reduced-motion emulation cancels a running WebGL ripple, prevents a new liquid effect and suppresses CSS transitions. Removing the preference permits the particle effect again. No real OS accessibility preference was changed.
- Muted text, placeholders, dark-theme accent controls, Portal drop-card copy, avatar initials, status/danger colours and connection-banner controls were corrected for contrast. Across source and package, 87 representative settled computed-colour samples (five themes plus the revoked-access banner) meet 4.5:1; the minimum observed sample is 4.888:1. Measurements wait for theme transitions to settle. They are not a complete WCAG audit or evidence of VoiceOver, all content/hover states, every GPU effect, physical touch or all browser engines.
- Explicit receiver disconnects release capture-owner peer/candidate queues. Media resumes after both Wall tabs reconnect. Owner disconnect/closed-client cleanup stops tracks, requiring a new share gesture.
