# Borderless experience direction

## Authority

PRODUCT.md records the user-approved working direction. The approval is provisional: the user will judge the completed experience. This file defines how to pursue that direction without drifting back into the rejected dashboard.

## Spatial thesis

The workspace is the room. Shared work fills the app window; controls sit above it only where useful. Files, notes and live windows share a spatial language and can be arranged together. People, settings and activity are floating utility windows, opened on demand and closed without altering the shared scene.

The operating experience is the priority. Its distinctive interaction is content crossing between devices and arriving as useful, manipulable work. Decoration, administrative scaffolding and marketing copy must not become the main event.

## First viewport

- Fill the available app area with the shared workspace; do not reserve a rail, sidebar, top dashboard band or bottom promotional band.
- Use compact floating room identity/actions and a compact tool dock. Avoid duplicate Send/Add/Share actions scattered across permanent chrome.
- Keep utilities closed until requested. Each can move, resize, close and return through an obvious control.
- Show actual content: readable text, images and live pixels. A large empty file-type card is not a substitute for the file when a safe preview exists.
- Keep presentation/display controls restrained. The work must remain legible on a large shared screen.

## Content windows

- Files, notes and live screens have clear owner/title, movement, resizing and focus/restore behaviour.
- Shared geometry/stacking is authoritative room state. Everyone viewing the room sees the intended arrangement.
- Keep live media elements and playback state alive through layout changes.
- A person's own utility-window geometry stays local; it must not reshape the room's content.
- Closing/stopping must communicate its actual consequence. Closing a utility is not deleting a contribution; stopping a live share ends capture.

## Across devices

### Phone to shared space

Select real content, see its destination, flick/swipe it towards that destination, then see a pending/confirmed arrival. Allow explicit Send and reduced motion. Physical phone acceptance remains required.

### Someone else's live screen

Show the chosen live screen/window as a movable surface on the room display or beside the recipient's own desktop work. Source changes continue to appear; the owner retains a clear stop control. Destination selection, consent and access must be real, not simulated presentation controls.

### Desktop edge handoff

Keep the original native goal: move a real application window beyond a desktop edge into the connected display space. Do not relabel a screen-share tile, browser window or edge glow as completion of this feature.

## Visual foundations

Preserve the Borderless name and current assets. Existing room themes may remain while the topology and interactions are corrected. The examples established behaviour, not a final palette or type specification. Do not invent a new brand or treat the old dashboard's component hierarchy as approved.

Use quiet, legible control typography, clear window hierarchy, solid readable utility surfaces, modest elevation and one coherent icon system. Motion should express departure, travel, arrival and direct manipulation; respect reduced motion and keep network success independent of animation.

## Acceptance and drift checks

Before calling a change aligned:

1. Does the shared workspace still fill the app when tools are closed and when they are open?
2. Can the user bring in content, see where it came from, move/resize/focus it and retain ownership?
3. Can the user dismiss room tools and recover them without losing work?
4. Do live windows continue updating while arranged, and does stopping a share actually stop capture?
5. Are flick/edge behaviours connected to real transfer or explicitly recorded as unimplemented?
6. Has the actual running experience been shown for user review, independently of passing tests?

Do not broaden retention, enterprise administration or release machinery at the expense of completing this experience. Keep the full delivery scope, but make the spatial experience the immediate build priority.
